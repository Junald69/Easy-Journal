# Easy Journal

キャッチコピー: 「Write Freely. Track Effortlessly.」

## このアプリは何か

Easy Journal は、バレットジャーナル風のデジタル手帳アプリです。
iPhone 向けで、画面は SwiftUI（Apple の画面づくりの仕組み）、記録の保存は SwiftData（アプリの中に記録を保存する仕組み）を使う予定です。

目指していることは、次のとおりです。

- 30秒で記録完了
- 毎日書かなくていい
- Monthly（月のページ）が中心で、Daily（その日のページ）は書きたいときだけ
- SNS・共有・アカウントはなし

設計資料は `docs/easy-journal-design.md` にあります。

## 開発の流れ

Mac は使いません。ビルドはGitHub Actionsで行う。
ビルドとは、書いたコードを、動くアプリの形に組み立てることです。

1. Windows でコードを書く
2. GitHub に送る
3. GitHub Actions（macOS）でビルドとテストをする（PR ではビルドと、全部のテストと、スクリーンショット。テストの中身は今までと同じ。main に取り込んだあとはビルドだけ。詳しくは下の「自動ビルド（CI）」）
4. のちに TestFlight で、自分の iPhone で確認する

TestFlight とは、正式公開の前に、自分の iPhone でテスト版を試すための Apple の仕組みです。

## ブランチとPRのルール

- main に直接コミットしない。作業は必ずブランチで行い、PR を作る。
  - ブランチは、作業用に分けた枝のことです。
  - PR（プルリクエスト）は、「この変更を main に取り込んでください」という GitHub 上のお願いです。
- 1チケット = 1つの PR。変更は小さくする。
- PR の説明は、やさしい日本語で「何を変えたか／どう確認するか／確認できなかったこと」を書く。
- PR の自動ビルド（CI）が緑（成功）になってから main に取り込む。この条件は、今回の変更でも変わらない。ただし、変えたファイルが `.md` と `docs/` の中のファイルだけの PR は、CI が動きません。そのときは、緑を待たなくてよいです。
  - CI とは、GitHub が自動でビルドやテストをしてくれる仕組みのことです。設定は `.github/workflows/ci.yml` です。失敗したときの見方は、下の「自動ビルド（CI）が失敗したとき、どこを見るか」に書きました。
  - main に取り込んだあとの CI はビルドだけです。取り込んでよいかの判断は、PR の CI が緑であることです。
- main への取り込みは Jun が行う。

## 守るルール

- `.xcodeproj` は Git に入れない（XcodeGen で作る）
- 型の名前は `JournalTask`（`Task` という名前の型は使わない）
- 外部ライブラリ（他の人が作った部品）を使わない
- SNS・分析・広告を入れない
- 秘密情報（APIキー、証明書、パスワードなど）をコミットしない
- 使い方に自信がないことは「要確認」と書く

## ビルド方法

ビルドとは、書いたコードを、動くアプリの形に組み立てることです。

このリポジトリには `.xcodeproj`（Xcode が開くプロジェクトのフォルダ）は入っていません。次の手順で作ります。

XcodeGen とは、`project.yml`（文字だけの設定ファイル）から Xcode のプロジェクト（`.xcodeproj`）を作る道具です。

1. XcodeGen を入れる。
2. このリポジトリのフォルダで、次を実行する。

   ```
   xcodegen generate
   ```

   実行すると `.xcodeproj` ができます。同じときに `App/Info.plist`（アプリの名前や画面の向きなどを入れる設定ファイル）も作られます。Info.plist は手で置かず、このコマンドに作らせます。
3. `.xcodeproj` は Git に入れない。コミットしない。
4. ビルドは GitHub Actions で行う。CI（GitHub が自動でビルドやテストをする仕組み）の設定は `.github/workflows/ci.yml` です。失敗したときの見方は、下に書きました。
5. Bundle ID（アプリをほかのアプリと区別するための名前）は `com.junald69.easyjournal` です。これは決定済みです。

いま仮にしている値は、次のとおりです。

- アプリ名: Easy Journal（仮）
- 最低 iOS バージョン: iOS 18.0（仮。U-01。安定して動くことを優先した仮の値）
- Swift の言語モード: Swift 5（仮。U-02）。設定の `SWIFT_VERSION` は `5.0`

## 自動ビルド（CI）が失敗したとき、どこを見るか

CI とは、GitHub が自動でビルド（書いたコードを、動くアプリの形に組み立てること）やテストをしてくれる仕組みです。

macOS（CI が動くパソコン）は、時間でお金がかかります。Free プランの無料枠は月 2,000 分で、macOS は 1 分あたり約 $0.062 です。1 分に満たなくても 1 分として数えます（1 分 22 秒は 2 分です）。「macOS は 10 倍消費」という記載、および無料枠をどれだけ消費するか（倍率）は、公式では未確認です。2,000 分がそのまま macOS の分数とは限りません。GitHub の予算アラート（Budgets and alerts。使いすぎを知らせる設定）を入れておくと安心です。

動くときと、どこまでやるか:

- main に向けた PR を出したとき、またはその PR に変更を足したとき: ビルドと、全部のテストと、スクリーンショット（画面の写真）までやる。テストの手順の中身は今までと同じ。同じ PR に続けて変更を送ると、古い実行は止まる（concurrency。同時に走っている古い方を止める仕組み）。
- main に取り込んだとき（main への push）: ビルドだけやる。テストもスクリーンショットもやらない。main への push では、実行中のものは止めない。

動かないとき:

- 変えたファイルが、すべて次のどれかだけのとき: `docs/` の中、`README.md`、どのフォルダにある `.md`（`**/*.md`。説明文のファイル）。
- paths-ignore（無視するファイルの指定）は、「変更されたファイルがすべて無視対象のとき」だけ動かさない。コードなど、ほかのファイルも一緒に変わっているときは動く。
- main 以外のブランチに変更を送ったとき

失敗したときは、次の順で見てください。ここに書く画面の名前は、このリポジトリの画面を実際に押して確かめていないので、違うときは「たぶん」と読んでください。

1. GitHub の PR 画面で、赤い×の「Details」を開きます。または、たぶん画面の上にある「Actions」タブから、その実行を開きます。
2. 失敗した手順（赤い×の手順）を開きます。ログの最後のほうにある `error:` の行を探します。
3. その実行の画面に、たぶん「Artifacts」という場所があります。そこに結果ファイル（`.xcresult`。テストの結果をまとめたファイル）があります。PR で、失敗してテストまで進んでいれば、あるはずです。テストの前で止まっているときは、まだ無いことがあります。main に取り込んだあとの CI はビルドだけで、テストをしないので、結果ファイルは残りません。
4. わからなければ、その PR の URL を Codie に伝えてください。

## スクリーンショットの見かた

スクリーンショットとは、画面を写真のように撮った画像です。

自動ビルド（CI）の結果ページに、「Artifacts」（できたファイルの置き場）があります。そこに `screenshots` があります。ダウンロードして、zip（まとめて圧縮したファイル）を開くと、PNG（画像ファイル）が入っています。スクリーンショットは PR のときだけ撮ります。main に取り込んだあとの CI はビルドだけで、スクリーンショットは残りません。

上の「自動ビルド（CI）が失敗したとき、どこを見るか」と同じで、ここに書く画面の名前は、実際に押して確かめていないので、違うときは「たぶん」と読んでください。

1. GitHub の PR 画面で、自動ビルドの「Details」を開きます。または、たぶん画面の上にある「Actions」タブから、その実行を開きます。
2. 実行の画面で、「Artifacts」を探します。
3. `screenshots` をダウンロードします。
4. ダウンロードした zip を開きます。中に PNG が入っています。

PNG が入っていないときは、その実行のログに「PNGが無い」と出ています。

iPhone でこの zip を開けないことがあるかもしれません（未確認）。開けなかったときは、Codie に伝えてください。

## 保存先

記録の保存場所は、App Group の中にします。

App Group とは、アプリ本体とウィジェット（ホーム画面の小さな表示）が、同じフォルダを共有できる仕組みです。

最初からこの場所に置く理由は、あとから別の場所へ移すと、すでに保存したデータの引っ越しが必要になるためです。

モデルのテストそのものは、メモリ上だけ、または一時フォルダのファイルで行います。メモリ上だけとは、ファイルを作らず、テストが終わると消える保存のしかたです。単体テストのテストホスト（テストと一緒に起動するアプリ本体）は、`-inMemoryStore` なしで起動し、本物の App Group を開きます。

ID（名前）は、次のとおりです。どちらも Jun さんが確定した値です。Apple 側に実際に登録できるか（ほかの人が使っていないか）は、Apple Developer Program に入ったあと（T-005 のあと）に確認します。

- Bundle ID（アプリをほかのアプリと区別する名前）: `com.junald69.easyjournal`
- App Group ID: `group.com.junald69.easyjournal`

App Group が実際に使えるかは、署名（アプリを作った人を証明する手続き）が必要です。この確認は、TestFlight の準備（T-005）のあとに行います。自動ビルド（CI）のシミュレーター向けビルドでは、確かめられません。

アプリの起動時に、保存の入れ物（ModelContainer。記録を入れておく箱）を作ります。ページを探す・作る処理は JournalStore にあります（下の「ページを探す/作る」）。起動時にページは自動では作りません。記録とタスクの操作は、下の「記録とタスクの操作」に書きました。繰越は、まだ入れていません。開き方の説明は、下の「データの保存と復元」です。

## データの保存と復元

- 保存先は、App Group（アプリ本体とウィジェットが共有できるフォルダ）の中です。
- アプリを閉じても、データは残ります。残ることは、テストで確かめます。
- 機種変更やバックアップの扱いは、いまは端末のバックアップ任せです。Phase 2（次の段階）で、書き出しを検討します。
- 保存先のフォルダが無いときは、起動時に作ってから開きます。SwiftData が自分でこのフォルダを作るかは未確認です。シミュレーターでは CoreData が復旧しました。実機で同じかは未確認です。署名つきで同じように動くかも未確認です。
- 保存先が開けないときは、別の場所に勝手に切り替えず、エラー画面を出します。
- 日や月を消すときは、中身ではなく目次カード（Page）を消します。Page を消すと、日ページ・月ページと、その中のタスクも一緒に消えます。中身だけを消すと、空の目次カードが残ります。
- データの形を変えるときは、バージョン管理（V1、V2。保存の形の世代）で引っ越します。詳しくは下に書きました。

App Group が、署名（アプリを作った人を証明する手続き）つきで実際に使えるか、バックアップに含まれるかは、未確認です。T-005 のあとに確認します。

### 保存の形を変える前に（V1 を固める）

いまの `EasyJournalSchemaV1` は、ファイルの一番上にあるクラスを、そのまま名前で指しています。配布したあとにモデルを変えるときは、変える前に、V1 をその時点と同じ定義で固めます。各バージョンが、自分のモデルを持ちます。

V1 を入れ子の enum（中にクラスを置く形）に固め、V2 を足します。`EasyJournalMigrationPlan` の `schemas` に両方を入れ、`stages` に `.lightweight(fromVersion:toVersion:)`（軽い引っ越し）か `.custom`（自分で書く引っ越し）を足します。入れ子にしたとき、保存上の名前（エンティティ名）が変わらないかは未確認です。V2 の作業の前に確かめます。この手順は、最初の配布（TestFlight）の前までに確定させます。

### 選択肢をあとから増やすとき

知らない文字を読むだけなら、決めておいた初期値に戻ります。ただし、新しいアプリで増やした値を、古いアプリが読んで保存し直すと、その情報は落ちます。配布後に enum（選択肢）の値を増やすときは、この点に注意します。

## 日付のルール（DateKey）

日付キーは `yyyy-MM-dd`（例：`2026-10-27`）、月キーは `yyyy-MM`（例：`2026-10`）です。暦は西暦のグレゴリオ暦（今ふつうに使う暦）に固定します。端末が仏暦や和暦でも、年は西暦です。渡された暦が仏暦などでも、中でグレゴリオ暦に直してから使います（タイムゾーンは引き継ぎます）。

「いつ」を決めるときだけ、端末のタイムゾーン（地域ごとの時刻のずれ）を使います。日付キー同士の計算は、タイムゾーンと関係なく暦だけで行います。夏時間（季節によって時計を進める・戻す仕組み）で1日の長さが変わっても、次の日の計算は影響を受けません。

「今日」は、呼び出すたびに計算します。保存しないし、前の結果を使い回しません。

画面側は、日付が変わったときに `todayKey`（今日の日付キーを返す処理）を呼び直します。日付が変わった通知は `NSCalendarDayChanged`、時刻やタイムゾーンの大きな変更の通知は `UIApplication.significantTimeChangeNotification` です。名前と、公式ドキュメントに書いてある動きは確認しました。受け取る処理は、このチケットでは作りません。実機でいつ届くかは未確認です。

- `NSCalendarDayChanged`: 端末の暦・地域・タイムゾーンで見て、日が変わったときに届く。スリープ中なら起きたときに届く。何日分もまとめて1回だけのことがある。届く時刻がぴったりとは限らない。
- `UIApplication.significantTimeChangeNotification`: 時刻が大きく変わったときに届く。例は、日付が変わるとき、通信会社による時刻の修正、夏時間の切り替え。追加の情報は付かない。

未確認：実機での動き。太平洋の Apia（サモア）で、暦に無い日 `2011-12-30` の日の始まりが何を返すか。

## タスクの状態のルール（TaskRules）

進み具合（progress）は `open`（□ 未完）、`partial`（◧ 一部）、`done`（■ 完了）です。繰越済み（isCarriedForward。翌日へ送った印）が true のときは、記号の横に `>` を付けます。

| 表示 | progress | 繰越済み |
| --- | --- | --- |
| □ | open | いいえ |
| ◧ | partial | いいえ |
| ■ | done | いいえ |
| □> | open | はい |
| ◧> | partial | はい |

- 記号のタップは □→◧→■→□ です。3回で元に戻ります。
- `>` 付きはタップしても進み具合は変わりません。取り消すと `>` だけが外れ、元の □ か ◧ に戻ります。
- 完了（■）は繰越できません。■> は作りません。繰越済みをもう一度繰越することもできません。

## ページを探す/作る（JournalStore）

日と月のページは、JournalStore（保存係。探す・作るを1か所にまとめたもの）だけが作ります。

- 同じ端末の通常の使い方では、1日1枚、1か月1枚をここで守ります。同じキーでもう一度呼んでも、新しいページは作りません。
- 同期（別の端末と記録を揃えること）や、別の処理が同時に動いて重複ができたときは、削除しません。中身があるものを優先し、その中で作った時刻が一番古いものを使います。中身があるものが無ければ、一番古いものを使います。時刻が同じなら id（識別子）の文字順が小さい方です。
- 重複の掃除（余分な方を消すこと）は、まだありません。

## 記録とタスクの操作

日ごとの記録（1行、気分、睡眠、習慣のチェック）と、タスクの追加・名前の変更・削除・進み具合の変更は、JournalStore（保存係）の関数を通します。画面はまだありません。

- 1行・気分・睡眠は、1日1件です。値を空にすると、その日の分を全部消します。今と同じ値をもう一度書いても、何もしません。
- 同じ日の記録が重なったときは、書くときに更新時刻が一番新しいものを使います。同時刻なら id（識別子）の文字順が大きい方です。読む関数も同じ選び方です。
- 気分は 1〜5。睡眠は 0.5〜24 時間で、0.5 時間きざみです。睡眠の日付は、起きた日です。
- 習慣のチェックは、同じ日にもう一度呼ぶと消えます。習慣の月と、記録する日の月が違うときは記録しません。
- タスクを変えるたびに、履歴（TaskHistory。何が起きたかの記録）を1件足します。前の履歴は書き換えません。進み具合は、画面から直接書かず、保存係の関数を通します。

## 繰越

未完（□）か一部（◧）の日のタスクを、翌日の Daily（その日のページ）へ送る処理です。画面はまだありません。JournalStore（保存係）の関数を通します。

- 翌日のページが無ければ自動で作ります。誰が作ったかは carryOver（繰越で作った、という印）です。あれば、タスク一覧の末尾に足します。
- 元のタスクは □> または ◧> になります。進み具合（どこまで進んだか）はそのままです。翌日には、同じ進み具合のコピーができます。
- 取り消すと、元は □ か ◧ に戻ります。コピーが作った直後のままなら消します。名前や進み具合を変えたあとは、コピーを残してつながりだけ外します。
- ページ同士のつながり（PageLink）は、取り消しても消しません。

## サンプルデータと起動オプション

起動時の引数（アプリを開くときに付ける印）で、見本の記録を入れられます。画面はまだ作りません。

- `-sampleData`（見本を入れて、という印）と `-inMemoryStore`（メモリ上だけの保存先、という印）が両方あるときだけ、2026年10月の見本を入れます。`-sampleData` だけでは入れません。本物の保存先（App Group。アプリ本体とウィジェットが共有するフォルダ）には書きません。
- 入れる処理は Debug ビルド（開発中の組み立て）だけです。Release（配布向けの組み立て）では何もしません。
- 見本の月はいつも 2026年10月です。いまの日付には左右されません。その月の月ページがすでにあれば、2回目は何も足しません。
- `-openPage` は、うしろの文字列を読みます。読めたときは、そのページを最初のページにします。例は `-openPage monthly:2026-10` です。読めないときは無視して、いまの月の記録（Monthly Log。月のページ）のままです。月の記録は、下の「Monthly Log の画面」です。それ以外は、まだ仮の画面です。

## ページの指定と URL

どのページを開くかは、次の文字列で表します。月の記録（Monthly Log）は、1日1行をその場で編集できる画面です（下の「Monthly Log の画面」）。月の習慣表と、その日のページは、まだ仮の画面で、ページの文字を出します。`-openPage monthly:2026-10` のように書くと、そのページが最初のページになります。

- 月の記録（Monthly Log）: `monthly:2026-10`
- 月の習慣表（Monthly Tracker）: `tracker:2026-10`
- その日のページ（Daily）: `daily:2026-10-27`

URL（ディープリンク。特定のページを直接開くための住所）は、次のとおりです。`easyjournal://` で始まる住所を、このアプリが受け取れるように登録する作業は、まだしません。

- `easyjournal://daily/today` … 今日の Daily
- `easyjournal://daily/2026-10-27` … 指定した日の Daily
- `easyjournal://monthly/today` … 今月の Monthly Log
- `easyjournal://monthly/2026-10` … 指定した月の Monthly Log
- `easyjournal://tracker/2026-10` … 指定した月の Monthly Tracker

`today` は、そのときに渡した「いま」の日付です。小文字だけを正しいとみなします。

## デザインの部品

色、余白、文字、方眼の背景は `Sources/DesignSystem` にあります。デザイントークンとは、色や余白に名前を付けて 1 か所に置いたものです。今後の画面も、ここから使います。

- 色: `paper`（紙の背景）、`ink`（文字）、`inkSub`（補助の文字）、`accent`（ボタンやチェック）、`grid`（方眼の線）、`todayBand`（今日の行の帯。accent を薄くしたもの。新しい色の数字は足していない）
- 余白: `xs`（4）、`s`（8）、`m`（12）、`l`（16）、`xl`（24）。単位は pt（点。画面上の長さ）
- 方眼: `GridPaperBackground`。1 マスは 20pt
- 文字: `heading`、`bodyText`、`subText`。大きさは iOS の「文字を大きく」に合わせます

色の数字は仮です。暗い画面（ダークモード）用の色は、まだありません。

## Monthly Log の画面

月の左ページ（Monthly Log。1日1行の一覧）では、文章の部分だけ、その場で1行を編集できます。◀（前の月）と ▶（次の月）で、月を移せます。Daily（その日のページ）を作る、日付を押して Daily へ移る、はまだできません。

- 上の ☰（目次）と +Daily は、押しても何も起きません。見た目だけです。日付の数字と曜日も、押しても何もしません。
- ◀ で前の月、▶ で次の月です。12月の次は翌年の1月、1月の前は前年の12月です。タイトル、Monthly Log、Monthly Task が、移った先の月になります。今開いている月は、画面と Router（今どのページかを覚える係）で同じです。アプリを開いたときは、今の月です。`-openPage` で月を指定したときは、その月です。日付が変わっても、開いている月は勝手に動きません。
- 文章を押すと、その場で1行を編集できます。空の日でも書けます。キーボードの確定、別の行を押したとき、編集欄からフォーカス（入力の対象）が外れたときに保存します。アプリが背面に回ったときも、空でない下書きは保存します。コントロールセンターや着信のように、一時的に前面を外れただけでは保存しません。文字を打つたびには保存しません。
- 文章がある行を、空（空白や改行だけ）にして確定すると、「この行を消しますか？」と確認します。確定は、キーボードの確定、フォーカスが外れたとき、別の行を押したときです。別の行を押したときは、確認が終わるまでその行へ移りません。「消す」でその日の行が消えます。「キャンセル」は元の文字に戻して閉じ、保存しません。背面に回ったときは確認を出せないので、空にする削除は保存せず、下書きと編集を残します。◀▶ で月を移すときも、空にする下書きは確認なしで消しません。確認を出して、月は移しません。「キャンセル」も「消す」も、その場の月のままです。月を移すには、確認を終えてから、もう一度 ◀▶ を押します。元々空の行を空のまま確定しても、確認は出さず、何も消しません。保存に失敗したときは、画面の下に「保存できませんでした」と出ます。入力した文字は残します。月も移しません。1行を保存したあとの読み込みに失敗したときも、入力を残して月は移しません。
- 今日の行は、薄い緑の帯です。土日は、日の数字と曜日だけ accent（落ち着いた緑）です。Daily がある日は、右端に小さな印があります。空の日は、空のままです。編集中の行は、accent の細い下線で分かります。新しい色は足していません。
- 開いたとき、今日の行が見える位置まで自動でスクロールします。今日がその月に無いときは、スクロールしません。月を移ったときも同じです。今日が移った先の月に無いときは、スクロールしません。日付が変わっても、開いている月はそのままです。
- 画面を開いただけでは、その月のページは作りません。◀▶ で移った先に月ページが無いときは、`findOrCreateMonthly`（月ページを探す。無ければ作る）で1枚作ります。すでにあれば、それを使います。同じ月へ何度移っても、月ページは増えません。保存に失敗したときは「保存できませんでした」と出て、月は移りません。移った先を読めなかったときは「記録を読み込めませんでした」と出て、月は移りません。今の月の表示と、入力した文字は残します。1行は、その月の日付の行だけを読みます。どの月ページについているかは見ません。選び方は、保存するときと同じです（更新が新しい方）。別の月の行は混ぜません。Daily の印は、その月の分だけ探します。タスクを追加したときも、その月のページを作ります。
- `-todayKey 2026-10-27` は、Debug ビルド（開発中の組み立て）で、かつ `-inMemoryStore`（メモリ上だけの保存先）のときだけ、「今日」をその日付に固定します。Release（配布向けの組み立て）では使いません。日付として読めないときは無視します。スクリーンショットを毎回同じ見た目にするためです。
- ページの下に「MONTHLY TASK」があります。高さはページの約4割までで、行が多いときはその中だけを滑らせます。1行を編集してキーボードが出ていても、タスクの記号はキーボードの上に残ります。＋ で名前を書いて追加します。記号を押すと □ → ◧ → ■ → □ と変わります。行の長押し「削除」は、「タスクを消しますか」と確認してから消します。キャンセルでは何も変わりません。1行を編集しているときにこれらを押すと、別の行へ移るときと同じように、先にその行の下書きを確定します。空にして消す下書きなら、行の確認を出して、タスクの操作は止めます。行の確認が出ているあいだは、タスクの操作はしません。月を移すときも同じです。追加欄に、空白以外のまだ確定していない文字があるときは、月は移りません。その文字は欄に残ります。空白だけのときは保存されないので、移れたときに欄を閉じます。移ったあとは、前の月のタスクや編集中の行は、新しい月に出しません。タイトルの編集、並べ替え、翌月への繰越、履歴の画面は、まだありません。前の月の習慣をコピーする処理も、まだありません。
- スクリーンショット（画面の写真）は、CI の Artifacts（できたファイルの置き場）の `screenshots` にあります。`01-monthly-today` は開いた直後、`02-monthly-top` は上までスクロールしたあと、`03-monthly-large-text` は文字を大きくしたとき、`04-monthly-edited` は1行を編集したあと、`05-monthly-delete-confirm` は行を空にしたときの確認、`06-monthly-task` はタスクを3つ足して □ ◧ ■ が並んだ状態、`07-monthly-november` は ▶ で11月を開いた状態です。
